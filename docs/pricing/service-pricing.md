# Service pricing

Reference: supplied GSS screenshots show a single-level fee category with name/sort/read-only, and a service item with category/name/cost/retail/sort/enabled/store. Implemented as per-store categories and items in pricing schema, migration 022. No demonstration business rows are inserted.

Features: categories/items list, name search, pagination 10/20/30/50/100, category sidebar, enabled filter, create/edit/copy/delete/batch-delete, CSV import/export. Copy opens an unsaved editable draft. CSV export uses the selected store and filters, maximum 10,000 records; formula-leading values are escaped. Import accepts UTF-8 CSV up to 1MB/100 rows, headers match exported file. Import saves rows sequentially and stops on first failure, explicitly reports the saved count (not an all-or-nothing import). For item import, categories must already exist in selected store. Exported rows serve as a format template; category and item exports have different headers.

Readonly category cannot be edited or deleted. Admin with update permission can explicitly unlock it; version is checked. It does not freeze child service items. Referenced categories cannot be deleted; users must remove/reassign items. Batch delete is atomic. Composite FK enforces item/category store match. Names unique by trimmed case-folded name, per store/category as applicable. Prices numeric(12,2), nonnegative; sort integer 0..999999. Patch uses version-based conflict detection under row lock.

API /pricing/categories and /pricing/items. All requests need effective basic.fee.read, and create/update/delete require their matching permission. Suppliers denied, store scope enforced server-side. Migration grants pricing codes to admin roles only; other roles can be explicitly assigned later. Cost redacted for non-admin users without viewCostPrice; item maintenance also requires cost access. Mutations audited without storing price payloads in log details.

Validation: isolated PostgreSQL schema and synthetic principals; CRUD, duplicate conflict, decimal validation, referenced category delete rejection, readonly lock/unlock, stale version conflict, scoped read denial, read-only principal write denial, cost redaction, atomic batch rollback. Typecheck/build passed; production read-only API smoke passed.
