# Current store context

The top selector is a view scope within the authenticated user's authorized stores. It does not grant or revoke store permissions. On change the query cache is cleared, active business page remounted, pagination/selection/edit/detail state reset. A central same-origin GET adapter inserts the selected storeId for customer/product/staff/pricing/purchase/supplier/warehouse list and overview endpoints; in all-store mode it preserves explicit page-level filters. It never rewrites writes, authentication, global settings or external requests.

Backend filters and totals use the requested authorized store. Product list previously lacked its store predicate; both counts and page query now enforce authorized stores (supplier-owned product access preserved) and selected-store filters. Staff, overview, supplier availability and warehouse lists also honor storeId. Existing customer/pricing/purchase predicates retained. Customer result-cache keys already include filters, separating store results. Store directory is still fetched in full authorized scope for the top selector and versioned master-data editing; the store listing itself is scoped in UI without sending a partial replacement that deletes unrelated stores. Store parameters and service pricing follow the current store. Shared brand/category dictionaries, roles and global security policy remain organizational settings.

Scope regression uses isolated restored DB with distinct records in two stores; customers/products/staff/purchase/pricing categories/items/suppliers/warehouses tested for all, A, B, count correctness and unauthorized scope rejection; overview tested per-store. Central adapter tested for selected override and auth/global/external/write exclusions. A latent missing supplier-role FK after demo cleanup was fixed by provisioning the minimum supplier role only when needed, never overwriting an existing role.

Header settings on store profiles now expand into a wrapping horizontal checkbox row below the toolbar, matching the staff page pattern; sticky index/actions always retained, default columns can be restored.
