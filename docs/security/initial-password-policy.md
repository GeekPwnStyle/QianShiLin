# Initial account password and voluntary password change

Administrator login username/display name: 杨法智. User explicitly requested initial password Admin@1234; it was applied once to the retained administrator, with old sessions invalidated. The credential verifier is bcrypt. The production reset SQL and pre-change backup are private /root/qsl-backups files, not an automatic migration that resets live passwords on replay.

Migration 024 adds identity.users.is_system_admin and changes password_credentials.must_change_password default to true. The root flag replaces checks against the literal login name admin in staff/user-access backend protection. Newly created staff accounts use data.name as username, ignore username/password body overrides for initial provisioning, and use Admin@1234. Supplier accounts use the actual contact name (or supplier business name when no contact is supplied), with the same initial password. Names must be unique; no silent synthetic username is assigned. Frontend initial-account inputs reflect these defaults.

Login and session responses include must_change_password. A dismissible theme-aware password dialog opens after login/session restoration when the flag is true. Later/cancel/close are supported and do not prevent business access. The flag remains true until a successful password change, so later logins remind again. Personal menu includes Modify Login Password for voluntary changes at any time. Login retains the original branded layout without the username/adjacent question-mark help.

POST /account/password requires an authenticated session and oldPassword/newPassword/confirmPassword. Server verifies old hash under row lock; new password length 8..24, uppercase/lowercase/digit/special, no whitespace, different from old/initial password, confirmation matches. On success, update bcrypt hash, clear reminder and failed attempts, retain current session, revoke other sessions, and write audit without password values. No mandatory change gate is imposed on other APIs.

Validation in isolated restored DB: initial-password reminder, wrong old password, strength/confirmation errors, successful replacement, old-password login denial, reminder cleared, current session retained, other session revoked. Staff provisioning test confirms real-name username, fixed default password, reminder flag and no inheritance of root flag. Typecheck and release build passed. Production initial-password login and normal store access passed. Browser interaction QA remains unverified because browser automation has been unavailable.
