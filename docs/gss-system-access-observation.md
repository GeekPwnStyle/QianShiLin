# 系统管理权限页核对与本项目实现

来源：2026-11-17，登录 GSS 后只读核对“系统管理 → 角色权限管理 / 用户权限分配”。

## 原系统观察

- 系统管理含参数设置、角色权限管理、用户权限分配、发送站内信、站内信发布记录、商品维护管理、门店资料、加工仓库设置、银行资料、操作日志、新手指引、初始化设置、期末处理。
- 角色权限管理：左侧业务菜单树，右侧按角色展开权限矩阵。矩阵列含“无权限、查看、新增、编辑、删除、导出、审核”。有新增角色、同步总店角色权限至其他门店、编辑角色、报表权限入口。内置管理员权限不可编辑。
- 用户权限分配：同样按菜单和操作展示矩阵，行是员工姓名及其所属角色。编辑弹窗中姓名与角色为只读；超级用户权限锁定，普通员工可调整权限。该页面不是直接编辑角色名称。

## 本项目当前落地

- PostgreSQL 保存角色、账号角色绑定、授权门店、个人减权项及变更审计。
- 角色权限页沿用本项目菜单树与功能权限点，保存走真实 API，不再写浏览器本地存储。管理员的系统访问和权限管理保底权限受到服务端保护。
- 用户权限分配页展示真实登录账号；可调整同身份类别的角色、授权门店，以及对该角色权限做个人禁用。个人禁用只能收紧，不能越过角色授予额外权限。
- 登录会话读取角色、门店范围和个人禁用项；采购 API 的读写和门店范围按服务端角色与账号配置校验。
- 品牌、供应商、加工仓库目录接口也校验角色权限与个人禁用；供应商资料仍按原有身份规则隐藏门店账号的银行字段。
- 操作日志参考 GSS 新版的月份筛选、检索和表格字段。现已记录登录、退出、角色权限变更和用户权限变更；每条记录保存当时的用户角色快照，避免后续改角色导致历史失真。角色和用户权限更新仍保留独立的前后状态审计表。

## 尚未等同原系统的部分

- GSS 的每个菜单 × 六种操作的完整权限矩阵尚未逐格映射到本项目权限码；当前展示的是本项目功能权限树。
- 新增/删除自定义角色、总店角色批量同步、报表专属权限、员工级直接授权、跨门店机构层级规则尚待核对。
- 现有部分演示模块仍使用前端模拟数据，角色配置不能代替这些模块未来的服务端行级授权。
- 操作日志目前只覆盖已接入真实后端的上述操作；尚未覆盖其他业务模块的新增、编辑、导出。原系统旧版/新版的更多筛选字段与日志详情仍需逐项复核。

## 内部公告与消息中心（2026-11-17）

原 GSS 的“发送站内信”提供类型、发件人、按门店/角色/人员选择接收人、重要程度、发送时间、正文与保存。“站内信发布记录”展示发送时间、接收人数、已读数、未读数和阅读详情。消息中心支持按类型、重要程度、阅读状态检索并标记已读。

本项目把发布与发布记录放在“系统管理 → 内部公告”，使用当前灰白卡片与亮黄绿强调样式。管理员可选全部用户、角色或具体用户，并按门店缩小范围；支持立即发布或 30 天内定时发布。发布时固定接收人快照，保留其当时角色和门店。每名接收人各有独立已读时间；管理员列表显示接收、已读、未读人数及“全部已读”状态，“阅读情况”弹窗逐人显示状态和时间，打开时每 15 秒刷新。用户顶部铃铛显示未读数量、摘要和历史公告；点开正文时标记当前用户已读。

API 与 PostgreSQL 迁移为 `apps/api/src/notices.js`、`apps/api/db/migrations/011_internal_notices.sql`。普通接收人的接口只返回本人公告，发布与阅读明细接口需管理员的 `system.notice.publish` 权限。演示登录继续保留，但不连接真实公告数据。
